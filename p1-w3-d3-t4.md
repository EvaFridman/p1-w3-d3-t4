# Частичный индекс

## 1. Поиск пользователей со статусом active без индекса

```sql
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE status = 'active';
```

Используется Seq Scan.

---

## 2. Частичный индекс по email для пользователей со статусом active

```sql
CREATE INDEX idx_users_active 
ON users (email) 
WHERE status = 'active';

EXPLAIN ANALYZE
SELECT email
FROM users
WHERE status = 'active'
AND email = 'user150000@mail.io';
```

Используется Index Only Scan using idx_users_active (частичный индекс применяется).

---

## 3. Поиск по email для пользователей со статусом blocked

```sql
EXPLAIN ANALYZE
SELECT email
FROM users
WHERE status = 'blocked'
AND email = 'user150000@mail.io';
```

Используется Seq Scan (частичный индекс не применяется, потому что мы ограничили использование индекса статусом 'active' при его создании).

---

# GIN по массиву

## 4. Поиск по массиву tags без индекса

```sql
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE tags @> ARRAY['sql'];
```

Используется Seq Scan, actual time = 0.021..33.568 ms.

---

## 5. GIN-индекс по массиву tags

```sql
CREATE INDEX idx_users_tags 
ON users USING GIN (tags);

EXPLAIN ANALYZE
SELECT *
FROM users
WHERE tags @> ARRAY['sql'];
```

Используется Bitmap Heap Scan (actual time=3.722..16.267 ms) с Bitmap Index Scan по индексу `idx_users_tags` (actual time=3.056..3.056 ms). Начал использоваться индекс, время выполнения запроса сократилось.

---

## 6. Сравнение размера обычного B-tree индекса и частичного индекса

```sql
CREATE INDEX idx_users_email 
ON users (email);
```

Размеры индексов через `\di+` в psql:

```
idx_users_active — 2672 kB
idx_users_email  — 7952 kB
```

Частичный индекс существенно меньше.
